# Banco de Preguntas — Entrevista MVP

Preguntas organizadas por bloque. Hacer 2-3 por mensaje.
No todas son obligatorias — adaptar al contexto del proyecto.

## Bloque A: Problema y Usuarios
1. ¿Qué problema concreto resuelve esto?
2. ¿Para quién es? Describe los roles de usuario
3. ¿Cómo lo resuelven ahora? (competencia/alternativas)
4. ¿Qué pasa si NO se resuelve? (urgencia/dolor)
5. ¿Cuántos usuarios iniciales esperas?

## Bloque B: Features Core
6. ¿Cuáles son las 3-5 funcionalidades imprescindibles del MVP?
7. ¿Qué funcionalidades explícitamente NO entran en el MVP?
8. ¿Hay flujos que requieran integración con servicios externos?
9. ¿Necesitas notificaciones? ¿De qué tipo (email, push, SMS)?
10. ¿Hay algún flujo que deba funcionar offline?

## Bloque C: Técnico
11. ¿Tienes preferencia de stack o estás abierto a sugerencias?
12. ¿Hay restricciones de hosting/infra? (presupuesto, región, proveedor)
13. ¿Auth necesaria? ¿Qué tipo? (email/pass, OAuth, magic link)
14. ¿Base de datos preferida? ¿Hay datos existentes a migrar?
15. ¿Necesitas API pública o solo consumo interno?
16. ¿Real-time necesario? (websockets, SSE)

## Bloque D: UX/UI
17. ¿Target principal mobile, desktop o ambos?
18. ¿Hay alguna app/web de referencia visual?
19. ¿Colores corporativos o logo existente?
20. ¿Requisitos de accesibilidad específicos?
21. ¿Multi-idioma necesario?

## Bloque E: Negocio
22. ¿Hay modelo de monetización previsto?
23. ¿Fecha objetivo o deadline?
24. ¿Quién más verá/evaluará esto? (inversores, clientes, equipo)
25. ¿Es proyecto personal, académico o profesional?
26. ¿Hay requisitos legales? (GDPR, LOPD, términos)

## Bloque F: Profundización (según respuestas)
27. "Has mencionado X — ¿puedes darme un ejemplo concreto?"
28. "¿Qué pasa cuando [edge case]?"
29. "¿Esto lo hace un usuario normal o un admin?"
30. "¿Con qué frecuencia se usaría esta feature?"

## Reglas de la Entrevista
- Máximo 3 preguntas por mensaje
- Si el usuario responde con audio, adaptar ritmo
- No repetir preguntas ya respondidas implícitamente
- Confirmar entendimiento antes de avanzar de bloque
- Al terminar, enviar resumen y pedir OK
